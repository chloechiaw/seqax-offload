v6e within-slice scaling. ONE host, no DCN anywhere. tokens/chip held fixed,
so batch scales with chip count and perfect scaling = IDENTICAL step time.

     8192      2     16      562     29,127      14,564        -
     8192      4     32      438     74,898      18,725    2.57x

4 -> 8 chips within a slice: exactly 2.00x. perfect linear scaling.
2 chips is the outlier -- with weights sharded only 2 ways each chip holds ~14 GiB of model
state instead of ~3.5, so it is memory-pressured, not interconnect-limited.

THE CONTROL RESULT:
  4 -> 8   chips, within one slice   2.00x   (perfect)
  8 -> 16  chips, across two slices  0.93x   (worse than not doing it)

same model, same code, same chips. the only difference is that the second doubling
crosses the slice boundary. the model scales fine -- the interconnect does not.
